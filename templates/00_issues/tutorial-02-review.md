# tutorial-02-review

この issue が終わったとき、自分の書いた page をレビューして直すサイクルを一周し終えています。

01 済 → **02 いまここ** → 03 自分のテーマで自走 → 04 週次メンテナンス

前回作った page は、まだ一度も読み返していません。

wiki は書いたら終わりではなく、読み返して直すことで使えるものになります。
今日はその直し方を覚えます。1 人で判断に迷ったとき別の LLM に相談する流れも、ここで通ります。

## 🌧️ Claude への指示

応答は次の 3 段で返してください。

1. 全 step の一覧を 2 行で出す。1 行目が現在地、2 行目が全体。済んだ step に `✓` を付ける

   ```text
   いまここ: ② 相談
   ① レビュー ✓ → ② 相談 → ③ 反映 → ④ 記録 → ⑤ FIXED → ⑥ commit → ⑦ exit
   ```

2. いまの step だけを説明する。先の step は説明しない。表は使わない
3. 末尾を「いまやること: <打つコマンド>」「そうすると: <何が起きるか 1 文>」で締める

最初の応答では、3 段に入る前に、この issue で何をやってどうなるかを 2-3 行で紹介してください。2 回目以降の応答には要りません。

1 回の応答で渡すコマンドは 1 つだけにしてください。次のコマンドを先に見せない。
Claude の応答が返らないローカルコマンドのときは、「終わったら『終わった』と伝えてください」と添えます。
最後の step は `/exit` です。次の issue に進めず、そこで区切ってください。issue 1 本が 1 セッションです。
`/exit` を案内する応答は、この回にやったことと、その結果できたものの要約から始めてください。どんな指摘が出て、何を採り何を採らなかったかを具体で書きます。
