# lw-update-issue

進行中 issue の 💧 進行中 / 🌂 中断点 / ☔ TODO を更新し、旧内容を 🪣 経緯に降ろす skill。
設計判断の why は `$KIT/docs/lw-kit/40_スキル設計/lw-kit-スキル設計-lw-update-issue.md`、本ファイルは実行手順の how。

入力: `$ARGUMENTS` は対象 issue のファイル名 / `[[link]]` / パス。省略時は会話文脈から推定する。

## Process 概観

```text
1. 対象特定 → 2. Read → 3. 日時取得 + 🪣 経緯に降ろす → 4. 💧/🌂 上書き → 5. ☔ TODO チェック → 6. ☔ TODO 追加
```

## 言い訳対戦表（起動前チェック）

| 言い訳                                                        | 現実                                                                                     |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 💧/🌂 に変化がないから何もしなくていい                        | ☔ TODO だけ変化している場合もある。変化がないなら「変化なし」と報告して skip            |
| 🪣 に降ろすほどの内容がない                                   | 会話で議論・決定したことも経緯の一部。💧/🌂 に書いてあることだけが「起きたこと」ではない |
| 旧 💧/🌂 を要約して短くまとめよう                             | 凝縮しない。lead が後から読み返して当時の流れを追える粒度で書く                          |
| 🪣 セクションが無いから更新できない                           | 無ければ自動追加する（☔ TODO の後、関連の前に挿入）                                     |
| 経緯の内容は分かってるから降ろしと上書きをまとめて 1 回でやる | ステップ 3 の `date` 取得を踏まないまま走る。降ろし（3）と上書き（4）は別ステップ        |

## 事前条件

- `.claude/rules/issue.md`（4 セクション構造・🪣 経緯のフォーマット）を把握している

## Process（6 ステップ）

### 1. 対象 issue の特定

`$ARGUMENTS` にファイル名 / `[[link]]` / パスがあればそれを使う。
無ければ会話文脈から推定する（直近で作業している issue、会話で言及された issue 等）。

候補が複数ある・特定できない場合は lead に「どの issue を更新しますか?」と確認して停止。

### 2. Read

対象 issue を Read し、現在の 💧/🌂/☔ の内容を取得する。
🪣 経緯セクションの有無も確認する（無ければ step 3 で自動追加）。

### 3. 日時取得 + 🪣 経緯に降ろす

`Bash(LANG=ja_JP.UTF-8 date '+%Y/%m/%d (%a) %H:%M')` で現在時刻を取得し、`### YYYY/MM/DD (曜) HH:MM` 見出しを生成する。

旧 💧/🌂 の内容と会話文脈を合わせて「このセッションで何が起きたか」をエントリ本文に書く。
💧/🌂 に書いてあることだけが「起きたこと」ではない。
会話で議論・決定・調査したことも経緯の一部。
💧 と 🌂 は別セクションだったものを 1 エントリにまとめるので、自然に読めるようにマージする。

書き方の粒度は lead が後から読み返して当時の流れを追えるレベル。凝縮しすぎない。

🪣 経緯セクションが無い場合は、☔ TODO の後・関連の前に `## 🪣 経緯` を新設し、降ろした内容を最初のエントリとして書く。

フォーマット注意: `###` 見出しの下に空行を入れる（markdownlint MD022 対策）。

💧/🌂 に変化がない場合は 🪣 に降ろす内容がないので skip。☔ TODO のみ更新があればそれだけ実行する。

### 4. 💧/🌂 上書き

会話文脈から最新の状態を書く。

- 💧 進行中 = いま何をしているか / 何が判明したか（状態の snapshot）
- 🌂 中断点 = 次にやること / 再開点（再開時の行動指示）

💧 と 🌂 で同じ next-step を重複して書かない。💧 は状態、🌂 は再開指示に役割分担する。

### 5. ☔ TODO チェック（活用）

今セッションで完了した項目を `[x]` にする。
変化なしなら skip。

### 6. ☔ TODO 追加（探索）

会話中に生まれた新しい作業を探す。
スコープ外に切り出した対応、別 skill への反映、後片付け、設計変更に伴う追従作業など。
見つけたら ☔ TODO に追加する。

🌂 中断点に書くだけでは足りない。☔ に落とさないと「全件 `[x]` = 完了」の判定が狂う。

該当なしなら「新規 TODO: なし」と報告して skip。

## エラーハンドリング

| ケース                               | 方針                                                                                 |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| `$ARGUMENTS` なし + 文脈から特定不可 | 「どの issue を更新しますか?」と案内して停止                                         |
| 候補が複数ある                       | 候補を列挙して lead に選択を促す                                                     |
| 対象 issue が WIP 以外（TODO 等）    | 更新は実行する（TODO / ICEBOX の issue も 💧/🌂 更新は有効）。ただし状態遷移はしない |
| 🪣 経緯セクションが未存在            | 自動追加する（☔ TODO の後、関連の前に挿入）                                         |
| 💧/🌂 に変化がない                   | 🪣 に降ろす内容がないので skip。☔ TODO のみ更新があればそれだけ実行                 |

## よくあるミス

1. 旧 💧/🌂 を要約して凝縮してしまう（lead が後から流れを追えなくなる、step 3 の趣旨違反）
2. 会話文脈を無視して旧 💧/🌂 だけコピーする（会話で議論・決定したことも経緯の一部、step 3 の趣旨違反）
3. 💧 と 🌂 に同じ next-step を重複して書く（💧=状態 / 🌂=再開指示の役割分担違反、step 4）
4. `###` 見出しの下に空行を入れ忘れる（markdownlint MD022 エラー、step 3）
5. 会話中に生まれた新作業を 🌂 に書くだけで ☔ に落とさない（「全件 `[x]` = 完了」判定が狂う、step 6 の趣旨違反。step 5 のチェックと step 6 の追加は探索・活用が逆なので別ステップにしている）

## 必須動作

- 💧/🌂 を上書きする前に、旧内容を必ず 🪣 経緯に降ろす（上書き後は復元できない）
- `/lw-update-issue` は対象 issue 以外のファイルに触らない（更新フローに閉じる）。issue の内容改訂は `log.md` に記録しない（規約は `.claude/rules/log-index.md`）
- 状態遷移（WIP → FIXED 等）はしない。状態遷移は `/lw-commit` の責務
