# skeleton-confirm

Claude が新規ファイルや大きい修正に着手する前に、骨子を lead に提示して合意してから書き始める。
理由は、書ききった後の巻き戻しは高コストで、書く前の骨子合意なら安いから。
広範囲な作業を計画する時は「最後にまとめて同期」のステップを設計せず、各ステップで都度反映する分解にする。

## 確認の流れ

1. 対象ファイルの宣言（`.doc-review.md`）と該当プロファイル・知見ファイルを Read する（レビューで毎回出る指摘を書く前に潰す）
2. 骨子をコードブロック付きで提示する
3. lead 応答を待つ（「OK」「ここ追加」「並び順変えて」等）
4. 応答を反映してから Write を実行する

## skip 指示

lead が `just write` 等で skip 指示した場合は骨子確認なしで書く。

## 骨子確認の対象

骨子確認必須（新規作成）:

- wiki page（`30_wiki/` / `40_project/` 新規 page）
- issue（`00_issues/` 配下の新規）
- rule（`.claude/rules/` 新規）
- Skill 一式（`.claude/skills/<name>/` 配下、SKILL.md 含む）
- 長文設計書 / README

骨子確認必須（既存ファイルでも「大きい修正」と判断したもの）:

- 全行リライト / 主要セクション全面書き換え
- schema 構造変更 / 規約変更
- 多数ファイルへの bulk 置換（複数ファイルの内容に踏み込む場合）

自走 OK（骨子確認不要）:

- 既存ファイルへの軽微な Edit / 行追記
- `log.md` / `index.md` の追記（CLAUDE.md ターン終了前セルフチェック準拠）
- frontmatter `updated:` 更新
- bulk 機械処理(`sed` 一括置換、`git mv` 等で個別ファイル内容に踏み込まないもの)
- `tmp` / worktree 内の一時ファイル

軽微かどうかを判定する前に、本題の内か外かを見る。
外なら「派生作業に降りる前に」を通す（派生は個々には軽微な Edit に見えるので、この順序でないと広さ確認が飛ぶ）。

「大きい修正」かどうかの判断材料（1 つでも当てはまれば骨子確認側に倒す）:

- スコープが広い（多数の行 / 多数のセクションに踏み込む）
- 構造変更（schema / 規約 / セクション順）
- 後で巻き戻すコストが高い
- lead が見落とすと困る変更

迷ったら骨子提示の側に倒す（聞く方が安いから）。

## 骨子の構成

骨子は対象ファイル全体の輪郭を見せる。lead が承認 / 修正指示を出せる粒度で:

- 何のファイル / どこに置くか
- 主要な観点・要素を一行説明で（細部の本文は書かない、「ここに書く」とだけ示す）
- 参照した実物（Read したファイル一覧）

骨子の形は対象ファイル種別ごとに変わる。詳細フォーマット（frontmatter / セクション構成 / 命名規約等）は対象ファイルの規約に従う。一律のテンプレに当てはめない。

良い骨子の例（rule 新規作成の場合）:

```text
配置: `.claude/rules/foo.md`（paths なし常時ロード、frontmatter なし）
冒頭リード（1-2 行）: foo の主張要約
セクション構成:
- やること: 主な指示の本体
- 例外 / skip 指示
- 関連: 根拠リンク 1 件
```

ファイル種別が違えば骨子の形も違う（issue なら「進行中」「中断点」「☔ TODO」、wiki page なら frontmatter 5 fields + type 別構成）。

## ワークフロー設計時の注意

広範囲な作業を計画する時の根本対策:

- 「最後にまとめて同期」「最後に反映」のステップを設計しない
- 各ステップで都度 issue / wiki / 関連ファイルに反映する分解にする
- 最後にまとめると、その最終ステップが「大きい修正」になり骨子確認が必要になる悪循環

issue の着地イメージや Phase 分解を設計する時に「最終同期」「最後にまとめて」が出てきたら、設計時点で「都度反映できないか」を検討する。

## 派生作業に降りる前に

本題の外のファイルを直したくなったら、着手の前に広さを一度見る。
同じ記述の写しが別の rule や wiki page にもあると、1 ファイルのつもりが 3 箇所以上になる。
写しの在りかは `grep -rl "<ファイル名>"` で当たりが付く。

広そうなら、その場では直さず記録に落として本題に戻る。
着手してから 1 commit で終わらないと分かった時も、その時点で戻る。
