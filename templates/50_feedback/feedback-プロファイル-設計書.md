# 設計書のレビュープロファイル

SKILL.md / 設計書 / ADR 等の技術仕様。
成功基準: 初見の読者が前提知識なしで設計の判断理由を追跡できること。

## 読み手の定義

対象文書が想定する配布範囲の外にいる読者。
設計の「何」ではなく「なぜ」を追跡するために読み、決定に至る会話には参加していない。

- 配布される文書（kit / OSS / 社外提供）→ clone して自分の環境で使い始める開発者。作者の環境での運用実績・issue 名・蓄積された feedback は見えていない
- 案件の設計書 → 後からチームに入る開発者。用語と前提はリポジトリ内の文書からしか学べない
- ワークスペース内の設計書 → 数ヶ月後に別の作業で読み返す自分と Claude。当時の文脈は失われている

対象がどれに当たるかは、その文書がどこまで配られるかで決める。

## 読み手

読者として通読し、次の 3 点を報告する（指摘の形式ではなく感想の形式で書く）。

1. 前提知識なしで「なぜこの形か」を追えた箇所
2. 詰まった箇所。説明のない用語、外部の文脈を知らないと意味が取れない記述、手元に存在しないファイルへの参照。どの文で詰まったかを引用で示す
3. 読んだ結果、その文書が想定している次の作業に着手できるか。できないなら何が足りないか

## 骨格

- 目標と非目標が明示されているか。
  非目標は「選べたのにあえて選ばなかった選択」か [seed]
- 代替案セクションがあるか。
  なぜ選定案が代替案よりマシかが比較されているか [seed]
- 未決事項が明示されているか。
  決まったことと決まっていないことの境界が曖昧でないか [seed]
- セクション間で粒度が大きく偏っていないか（1 節だけ異常に詳細、他が概要だけ等） [seed]
- 先行例から型を写した文書では、先行例自身が上位規約に違反している行まで写していないか。既存文書との一致だけを見ると、規約と実物が両方ずれた状態で揃う [seed]

## 中身

- SSOT 境界の明示: 設計書と SKILL.md の役割分担（設計書=why、SKILL.md=具体値の正本）が冒頭で宣言されているか [confirmed]
  実装が既にある設計書では、宣言だけでなく表・列挙・条件式の写しが残っていないかも見る。
  実装前（SKILL.md が未作成）の設計書は実装に踏み込んだ記述を持ってよく、指摘対象にしない。
  一時重複は SSOT 違反ではなく処方の予約で、解消は実装 + 動作確認の後 [confirmed]
- allowed-tools と本文の一貫性: allowed-tools に含まれないツールを本文が前提にしていないか。逆に allowed-tools に含まれるのに本文で使われないツールがないか [confirmed]
- 自己完結性: この文書だけで設計判断の理由が追えるか。
  外部文脈なしで成立するか [seed]
- 配布範囲の外への依存: 読者の手元に存在しないもの（配られないディレクトリ・ファイル、環境変数、別リポジトリの実装、その環境でしか成立しない運用）を前提にしていないか。
  前提にする場合、読み替えの指示があるか [confirmed]
- 用語の一貫性: 同一概念に複数の名前を使っていないか（設計書で最も実害が大きい不統一） [confirmed]
- トレードオフの明示: 「こうした」だけでなく「こうした結果、何を犠牲にしたか」があるか [seed]
- 曖昧語の排除: 「適切に処理する」「パフォーマンスを考慮」等の解釈が割れる表現がないか [seed]
- 前提と結論の整合: 背景で述べた問題が、提案設計で実際に解決されているか [confirmed]
- 判断項目と後続指示の整合: 前段で設定値を判断させる項目があるとき、後続の指示がその判断で分岐しているか。分岐すべき指示が単線だと、片方の判断を選んだ読者に成立しない指示が残る（例: `disable-model-invocation: true` を選んだのに description の英語化を無条件に要求する） [seed]
- 理由付けの裏付け: 「〜という判断による」「〜のため採用した」の理由が、実際の決定記録（issue / 経緯 / commit）に対応しているか [confirmed]
  実装に合わせて設計書を書き直す時に、書き手が空欄を埋めるつもりで理由を推測補完しやすい。
  推測の理由は次に読む人が確定した判断として扱うため、記録がないなら「記録に残っていない」と書く方が正しい。

## 文章

- 口語的な比喩: 「腐る」「空振りする」「痩せる」「濁す」等で説明せず、何が起きるか（参照が解決しない / 該当なしで終わる / 実態と乖離する）を書けているか [confirmed]
- 属人的な表現: 「〜に染み付いている」「思い出して開かなければ」等、特定の人の習慣に依存した言い方になっていないか [confirmed]
- 置換後の係り受け: 用語を差し替えた箇所で主語と述語が噛み合っているか（「反映が何も検出できない」等） [confirmed]

## 表記

- 図と本文の一致: ダイアグラムがある場合、本文の説明と食い違っていないか [seed]
- セクション間の参照整合: 「詳細は X セクション参照」の先に実際にその内容があるか [confirmed]
