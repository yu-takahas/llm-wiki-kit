# Claude-Codeステータスラインの組み方

ステータスラインのスクリプトを自分で書く時の判断材料。
機構そのものの仕様（設定キー・更新契機・入力フィールド）は [[Claude-Codeのステータスライン]] が持つ。
本ページは「何を出すか」「どう組むか」に絞る。

## 表示要素の選び方

1 行に収まる情報量には限りがあるので、出す順に優先度を付けて削る。

優先度の目安は、git ブランチ > モデル名 > 作業ディレクトリ の順。
ブランチが最上位なのは、エージェントが作業中にブランチを切り替えるため、人間側が見失いやすいことによる。

色はアクセント 1 色に絞り、そこに太字を重ねる。
要素ごとに色を変えると、どれが重要かの手掛かりが消える。
色に意味を載せる例としては、ブランチ名で色を変えて保護ブランチを目立たせる方式がある。

並列作業では「いまどの worktree のどのブランチか」が最優先になる。
この場合は 2 行出力にして、1 行目をセッションの数値、2 行目を git の所在に割り当てる構成が取られる。

## 値の取り出し

`jq` でフィールドを取り、無い時のフォールバックを必ず置く。

- 数値: `// 0`
- 文字列や任意フィールド: `// empty`（値が無ければ何も出力しないので、後段で空判定できる）
- 真偽値: `//` は `false` を「無い」と扱うので使えない。`.prompt_cache.warm == false` のように比較で書く
- 文字列の整形: `split` は空文字に対して空配列を返すので、`split(" (")[0]` は入力が空の時に `null` を出す。フォールバックを通した後でも `null` の文字列が表示に混ざる。`sub` を使うか、添字の後にもう一度フォールバックを置く

最初の API 応答が返るまで `context_window.used_percentage` は `null` になる。
`rate_limits` と `prompt_cache` はそもそも現れないことがある。
どちらも「無い前提」で組む。

## 利用枠の表示

`rate_limits.five_hour.used_percentage` と `.seven_day.used_percentage` を `printf '%.0f'` で丸めて並べる。
`resets_at` は epoch 秒なので、`date -r` で時刻に直すとリセットまでの見当が付く。
5 時間枠をバーにしてリセット時刻を添える構成が、実装例として公開されている。

利用枠の `resets_at` に達すると、直前にスクリプトへ渡された値を見て Claude Code 側が再実行を掛ける。
つまりリセット直後の表示は放っておいても更新される。

## キャッシュ温度の警告

`prompt_cache.caching_observed` が `true` かつ `warm` が `false` の時だけ「冷えている」と表示し、原因に `last_miss_cause.causes[0]` を添える。
`caching_observed` で門を作らないと、キャッシュを報告しないプロバイダで常に冷えているように見える。

## 重い処理のキャッシュ

`git status` / `git diff` はステータスラインの実行頻度に対して重く、そのまま呼ぶと表示が遅れる。
結果を一時ファイルに書き、mtime が N 秒より古い時だけ再取得する。

ファイル名に `session_id` を含めると、複数セッションが同じキャッシュを奪い合わない。

外部 API を叩く実装では 2 層に重ねる方式が取られている。

- API 応答を 5 分保持する層
- その上にシェル側で 60 秒 TTL を重ねる層
- 失敗時は古い値を印付きで返す（エラーで空にしない）
- ロックファイルで同時実行を防ぎ、ロックは 30 秒で自動失効させる

ステータスラインが空になる条件（非ゼロ終了・無出力）を踏むより、古い値を出す方が実用上は良い。

## 幅への適応

`COLUMNS` 環境変数を読み、狭い時は要素を落とす。
`tput cols` は使えない（stdout が端末に直結していない）。

公式ドキュメントは `COLUMNS` が渡ることだけを書いていて、適応の実装例までは示していない。
コミュニティ側では `ccstatusline` が flex セパレータで右寄せと幅吸収を持つ。

## クリック可能リンク

OSC 8 エスケープでリポジトリや PR の URL を貼れる。
`echo -e` よりも `printf '%b'` の方がシェル差に強い。

## subagent 用の行

`subagentStatusLine` は agent パネルの各行の本文を差し替えるキー。
メインのステータスラインとは入出力の形が違う。

- 入力: 1 回の実行で、見えている行すべてが 1 個の JSON として届く。`tasks` 配列の各要素が `id` / `name` / `type` / `status` / `description` / `label` / `startTime` / `model` / `effort` / `contextWindowSize` / `tokenCount` / `tokenSamples` / `cwd` を持ち、使える行幅は `columns` に入る
- 出力: 上書きしたい行ごとに `{"id": ..., "content": ...}` を 1 行ずつ stdout に書く
- `id` を出さなければその行は既定の描画のまま、`content` を空にするとその行が消える

`tokenCount` と `contextWindowSize` が揃うので、行ごとのコンテキスト使用率を出せる。

## 自作せずに済ませる選択肢

| ツール              | 形                        | 特徴                                                             |
| ------------------- | ------------------------- | ---------------------------------------------------------------- |
| `ccstatusline`      | TypeScript（React + Ink） | TUI で対話設定、Powerline、テーマ。`bunx -y ccstatusline@latest` |
| `claude-statusline` | Go 単一バイナリ           | Starship 風。設定ファイルのフォーマット文字列とプリセット 6 種   |
| `starship-claude`   | 設定同梱                  | 事前構築の Starship 風設定                                       |

`ccstatusline` が持つウィジェットの分類は、自作する場合も「出せるものの一覧」として使える。

- モデル / セッション: モデル名、セッション名、セッション時間、セッションコスト、アカウントのメールアドレス
- トークン: 入力 / 出力トークン、コンテキスト長、窓サイズ、使用率、バー
- 速度: 入力速度、出力速度、合計速度
- 利用枠: セッション枠、週次枠、モデル別の週次枠、枠のリセットタイマー、追加利用分
- git: ブランチ、状態、PR / MR、SHA、衝突、ステージ状況、追加 / 削除行、ahead / behind、worktree 名とブランチ、origin / upstream の所有者とリポジトリ名
- Jujutsu: ブランチ、状態、リビジョン
- 環境: 作業ディレクトリ、メモリ使用量、音声状態、vim モード、思考の effort、サンドボックス状態
- キャッシュ: 残り時間、ヒット率、読み取り、書き込み
- その他: 圧縮回数、ブロックタイマー、任意コマンド、任意テキスト、任意記号、リンク

設定は `~/.config/ccstatusline/settings.json` に置かれる。
行数の上限は撤廃され、幅は自動検出される（`CCSTATUSLINE_WIDTH` で上書き可）。
Powerline が横幅を食う問題に対しては、ラベルを落として値だけにするモードと片側だけのパディングが後から入っている。
