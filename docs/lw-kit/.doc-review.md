## プロファイル

宣言 glob によるプロファイル判定（自動判定の第 2 段階）:

- `lw-kit-スキル設計-*.md` → 設計書
- `lw-kit-*.md` → 設計書
- `.claude/skills/**/SKILL.md` → 設計書
- `.claude/rules/*.md` → 設計書
- `CLAUDE.md` → 設計書
- `README.md` → 技術ブログ（成功基準が「読み手が手順に従って同じ結果を再現できる」で一致する。読み手がスキャンで読む点も同じ）
- `00_issues/.guide/*.md` → 設計書

上記以外（`knowledge/*.md` 等）は第 3 段階の type 対応表に委譲。

## コンテキスト

### 規範

規範は原則 `$KIT/docs/knowledge/` 配下から取る。
llm-wiki-kit は外部公開する kit として単体で完結させる必要があり、設計書本文は利用側リポジトリ（`30_wiki/` 等）に依存させない。

例外はワークスペース側の蓄積 2 種（下記の `50_feedback/` 配下）。
失敗事例と知見は「この環境で実際に踏んだ」記録で、kit に配る性質のものではないため取り込まない。
レビュー時にだけ参照する（kit の配布物には含まれないので、単体完結の要件とは衝突しない）。

- `$KIT/docs/knowledge/Claude-Code-Skillの書き方.md` — SKILL.md / rules のレビュー時
- `$KIT/docs/knowledge/Claude-Codeのメモリ階層.md` — CLAUDE.md / rules / skills の配置判断
- `$KIT/docs/knowledge/Progressive-Disclosure.md` — SKILL.md のレビュー時（本文を最小に保ち詳細を別ファイルへ逃がす公式原則。肥大・外出し判断の根拠）
- `$KIT/docs/knowledge/レビューワークフローの設計原則.md` — レビュー系 skill（doc-review / fix-review / code-review）のレビュー時のみ渡す
- `$KIT/docs/knowledge/プロンプト設計原則.md` — プロンプト系文書全般
- `50_feedback/feedback-観察-失敗事例.md` — SKILL.md / rules のレビュー時（Claude の失敗パターンとの照合）

上のリストとは別に、対象ファイルに対応する設計書があれば、それも規範として渡す。
設計書は実装と一対一で置いているので、`$KIT/docs/lw-kit/` 配下を対象のファイル名、または対象が属する仕組みの名前で検索すれば見つかる。
無ければ規範なしで続行する（リストに個別の対応を足さない）。
