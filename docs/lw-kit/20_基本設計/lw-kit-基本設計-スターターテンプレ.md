# llm-wiki-kit のスターターテンプレ

`setup.sh` がワークスペースに配布する初期ファイル群の選定基準。

**本ページは配布物の選定基準のみを持つ。**
配布する個々のファイルとその中身は `templates/` 配下の実物が正本で、本ページに写さない。

## 選定の軸

配布するかどうかは 3 つの軸で決める。

### 1. skill が実行時に読むものは全量配る

skill 本体と、skill が動く過程で読む rule / guide / レビュー宣言 / レビュープロファイル / permission 設定 / lint 設定を、部分配布せず一式で同梱する。
[[lw-kit-要件定義-ペルソナ]] の P2 は「仕組みは自分で作りたくない、出来合いのものに乗りたい」層で、部分配布だと残りを自分で組む作業が発生する。

全量配っても固定にはならない。
[[lw-kit-要件定義]] のアーキテクチャ要件が「各自が skills / rules / wiki 規約を自由にカスタマイズしてよい」と決めており、配布物は完成品ではなく改変の出発点として置かれる。

代償として、初日に見えるファイルは増える。
[[lw-kit-要件定義-ペルソナ]] の P1 は概念の多さで離脱しうるので、この代償は「概念を段階的に出す」チュートリアル側（軸 2）で受け止める。
配布は全量、導入は段階という分担にしている。

### 2. 初回体験を成立させるものを同梱する

チュートリアル issue を配る。
道中で使う仕組みは軸 1 で既に配られているので、この軸が単独で配布を決めるのはチュートリアル issue 本体になる。

[[lw-kit-要件定義]] の機能要件が「初回 30 分で 1 本 wiki を作る成功体験」を要求し、[[lw-kit-要件定義-ペルソナ]] は P1 / P2 共通の設計への示唆として「初回 30 分の成功体験が生命線」を挙げている。
チュートリアルの途中で「これは自分で用意してください」が出ると、この 30 分が切れる。

### 3. 個人に紐づくものは配らない

[[lw-kit-要件定義]] の非機能要件「秘匿情報の排除」による。
auto memory（ユーザー個人の好み）が配布対象に含まれないのも同じ理由（[[lw-kit-詳細設計-CLAUDE.md]]「層の使い分け」）。

## 蓄積系のファイルは器だけ配る

蓄積系のファイル（`50_feedback/` の観察・ルートのメタファイル・`20_library/library.md`）は、器と追記の手順だけを配り、蓄積された中身は配らない。

判定の基準は「読み手が誰か特定できるか」で、実運用由来かどうかではない。
観察の事例は書いた本人の環境に紐づくので、中身ごと配ると利用者が他人の観察を引き継ぐことになる。
一方でレビュープロファイルは実運用で積んだ観点をそのまま配っている。文書種別ごとの読み手と成功基準は誰が書いても同じ形になり、特定の個人に紐づかないため。

行動指針は記入例を入れて配る。
空の器だけでは何を書く場所なのかが伝わらず、記入例があると 1 件目を書き始められる。
記入例に選ぶのは llm-wiki-kit の利用者が共通して使える汎用的な指針のみで、特定個人の心理特性や好みに紐づく指針は除外する。

## `docs/knowledge/` を配らない理由

knowledge は kit を理解するための参考 wiki で、ワークスペースが動くのに要らない（軸 1 / 軸 2 のどちらにも当たらない）。
全部配ると、使わない page が初日から `30_wiki/` に並び、利用者が自分で書いた page と混ざる。
必要な page だけを手動で cp する運用にしている（取り込み時の手順は [[lw-kit-基本設計-ディレクトリ構成]]「`docs/knowledge/` を取り込む時」）。
