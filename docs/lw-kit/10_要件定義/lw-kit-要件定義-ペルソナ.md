# llm-wiki-kit-ペルソナ

llm-wiki-kit のターゲットユーザー分析。
P1 がメインターゲット、P2 はより広い層へのリーチ。
kit の現機能はナレッジ管理ワークフローとして完成しており P1 に即応できる。P2 は README の見せ方とチュートリアルの導線で拾う。

## P1: 感度の高い新規ユーザー

Claude Code を日常的に使っている。
Obsidian も触ったことがある。
ナレッジ管理に課題感があり、「LLM で wiki 管理」に興味を持てるリテラシー。
GitHub で見つけた / 友人に勧められた、どちらもあり得る。

ゴール: 自分のナレッジ管理ワークフローを LLM で改善したい。

## P2: LLM で設計書もやりたいと思い始めた人

Claude Code はコーディングエージェントとして使っている。
Copilot の tab 補完や Claude Code の Plan でコードを書かせるのが主な使い方。
設計書や仕様書も LLM で書けたらいいなと薄々思っているが、やり方が分からない。
wiki や Obsidian は「聞いたことはある」程度。

コードは書けるし、LLM の可能性も感じている。でも何から始めればいいか分からない。

ゴール: 設計書やナレッジ管理も LLM でやりたい。手順さえ分かれば始められる。

## P1 エンパシーマップ

### Says

- 「Claude Code で wiki 管理って面白そう」
- 「とりあえず動かしてみるか」
- 「skill と rule って何が違うの？」
- 「自分の仕事に合わせて変えていいの？」

### Thinks

- Obsidian にメモは溜めてるけど整理できてない
- LLM に手伝わせたら回るかも
- セットアップが面倒だったらやめるな
- 概念多そうだけど全部覚えなきゃダメ？

### Does

- README を 30 秒で判断する
- `setup.sh` を叩いてみる
- チュートリアルの最初の数ステップを試す
- skill の中身を覗いて動きを理解しようとする

### Feels

- 興味: LLM x wiki の可能性
- 不安: 概念が多い、使いこなせるか
- 苛立ち: 動かない時に何が悪いか分からない
- 達成感: 初めて自分の wiki ページが生成された瞬間

### 核心

痛み: 概念の多さ（issue / wiki / raw / library / feedback / skill / rule...）を一度に浴びると「自分には重い」と感じて離脱する。

欲求: 「叩いたら動く → 1 本 wiki を作る」までの成功体験が 30 分以内に欲しい。

## P2 エンパシーマップ

### Says

- 「設計書も LLM で書けたらいいのに」
- 「コードは Claude Code で書いてるけど、ドキュメントは手書きなんだよな」
- 「wiki ってどうやって始めるの？Obsidian？」
- 「skill とか rule って何？自分で設定できるの？」

### Thinks

- コードだけじゃなくて設計書も LLM に手伝わせたい
- でも何をどう整理すればいいか分からない
- 仕組みがあるなら乗っかりたいけど、自分で仕組みを作る余裕はない
- セットアップが面倒だったらやめるかも

### Does

- Copilot で tab 補完、Claude Code の Plan でコード生成
- ドキュメントは最低限（README / コメント程度）、もっとやりたいとは思っている
- 情報は頭の中 or チャット履歴で管理（散逸している自覚はある）
- README を読んで「これなら始められそう」と思えるかで判断

### Feels

- 期待: 「コード以外にも使えるならやってみたい」
- 不安: 「自分にできるレベルの話なのか」
- 面倒: セットアップが重いと「今度でいいか」になる
- 達成感: 初めて設計書が LLM で生成された時の「これこれ！」

### 核心

痛み: 設計書やナレッジ管理も LLM でやりたいと思っているが、やり方が分からず始められない。コードのワークフローはあるのに、ドキュメントのワークフローがない。

欲求: 「これをやれば始められる」という明確な手順。仕組みは自分で作りたくない、出来合いのものに乗りたい。

## 設計への示唆

### 共通（P1 / P2 とも）

1. 初回 30 分の成功体験が生命線 — チュートリアルの step 4-5（research → render）が最重要区間。P2 は wiki 概念自体が初めてなので特に切実
2. 概念は段階的に出す — 初日に全ディレクトリの意味を覚えさせない。チュートリアルで触るものだけ説明
3. `setup.sh` はエラーに強くする — 最初の離脱ポイント
4. 最小運用でも回る — weekly / feedback / library は任意。`30_wiki/` に書くだけで価値が出る設計

### P2 固有

1. README で「設計書 / ナレッジ管理を LLM で」を前面に出す — コーディングの延長として見せる
2. 案件横断の設計書置き場 + `add-dir` でコードリポジトリと併用する使い方をガイドする
3. 仕組みは出来合いを提供する — P2 は自分で作りたくない、乗りたい
4. Obsidian がなくても完走できる建て付けにする（初出で「Obsidian があると `[[link]]` が辿れる（無くても動く）」と一言入れる）
